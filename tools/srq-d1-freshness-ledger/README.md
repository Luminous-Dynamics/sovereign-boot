# SRQ D1 freshness ledger (reference implementation)

## Purpose

This dependency-free Rust crate implements one narrow building block for a future D1 path: bind a result from an external attestation verifier to a fresh, single-use challenge, and reject replay, expiry, and target/policy/artifact mismatch. The consuming state transition is serialized by a mutex; one correctly bound response marks the challenge consumed atomically.

## What it enforces

- Challenge IDs are 32 CSPRNG-generated bytes encoded as 64 lowercase hexadecimal characters. This crate validates the representation but does not generate randomness.
- Challenges bind a target ID, policy digest, artifact digest, issue time, and exclusive expiry time.
- The caller passes the current Unix time and a monotonic-nanosecond reading. The monotonic deadline prevents a backward wall-clock adjustment from extending challenge lifetime.
- Evidence observation time must fall inside the issue/expiry window and cannot be later than current wall time.
- The first correctly bound appraisal consumes the challenge. The same challenge cannot be consumed again; a binding mismatch does not consume it.
- Expired and consumed IDs remain in memory; the ledger fails closed at configured capacity rather than evicting replay history.

## Explicit non-claims

This is not a complete remote-attestation system or production D1 qualification. The crate does not verify signatures, TPM quotes, certificate chains, measured boot, artifact contents, or verifier policy. The AppraisedEvidence input must come from an independently trusted verifier, and the caller must authenticate that record before using this API. Digest-shaped strings and a verifier ID are identifiers, not cryptographic proof.

The store is volatile, process-local, and not crash durable. Restarting the process loses its replay history. Production use requires a durable transactionally updated store, challenge CSPRNG, protected time source, signed/verified evidence, authenticated verifier policy, defined key rotation/revocation, and an independently reviewed relying-party decision. It does not issue an SRQ release PASS.

## Initial acceptance criteria

- Exactly one success under 64 concurrent submissions of the same valid response.
- Wrong target/policy/artifact, malformed IDs/digests, expired/rollback/future timestamps, duplicate issuance, and capacity exhaustion reject fail-closed.
- A bad binding does not burn a challenge that can still be correctly consumed before expiry.
- No custom cryptographic algorithm or random-number generator is included.
